# Privacy and account lifecycle

FinanceHub provides authenticated data export and permanent account deletion under **Privacy** in the application navigation.

## Data export

`GET /api/privacy/export` downloads a JSON document generated by the `export_my_data()` database function. The function derives the user ID from the validated JWT and exports only rows owned by that user. It includes:

- account identity metadata (ID, email, creation and last sign-in timestamps);
- family membership;
- manual expenses, budgets, savings goals, EMIs, and notifications;
- financial accounts, connection metadata, import runs, raw/imported transactions, matching rules, and transaction audit history.

The export does not contain another family member's user-owned records, the family invite code, passwords, auth tokens, service keys, or receipt file contents.

## Deletion safeguards

Account deletion requires the exact confirmation phrase `DELETE MY ACCOUNT`.

Before deletion, `get_account_deletion_status()` checks family ownership:

- a regular member can delete their account;
- a family head can delete only when no other user has a current membership or surviving family-linked records;
- a family head with other members or former-member data is blocked, because deleting the owning auth record would cascade-delete shared family data.

A blocked head must first transfer ownership (when that feature is available) or remove the remaining members. The API never bypasses this guard.

`begin_account_deletion()` locks the family row used by invite-code joins, rechecks all destructive-cascade conditions, and temporarily disables invitations. Failed external cleanup restores the prior invitation state.

The API lists and removes the user's private receipt objects before calling the Supabase Admin Auth deletion endpoint, because Supabase rejects deletion of a user who still owns Storage objects. If receipt cleanup fails, the Auth user is not deleted. Database foreign keys then cascade user-owned relational rows after successful Auth deletion. Logs contain only status, count, and correlation ID—never object names, email addresses, tokens, or financial data.

## Required server secret

Permanent deletion requires this API-only environment variable:

```text
Supabase__ServiceRoleKey=<Supabase project service-role key>
```

Set it in the backend hosting provider (for example, Render). Never put it in Angular environment files, GitHub variables, logs, screenshots, or source control. The browser continues to use only the public anonymous key.

Data export and deletion preflight do not use the service-role key; they execute with the user's JWT and database-enforced scope. The service role is used only for the final Admin Auth deletion and receipt cleanup.
